01全流程：七步，與誰做什麼

每一步都是同一個循環：提方案 → 你選 → 派工 → 檢查 → 你看 → 修改。

步驟你做agent／程式做
1　腳本決定講什麼、每句講一件事、縮寫唸法寫初稿、查證、整理成資料
2　配音選聲音、戴耳機聽過合成、切句、入庫
3　時間軸不用做逐詞對時，產生所有時間點
4　生圖從 3 種畫風選 1 種生圖、放大、去背、切件
5　鏡頭與渲染看靜圖、說哪裡不好看寫動畫程式、逐格算、出片
6　自動檢查不用做擋住「一定錯」的六類
7　看片修改「時間＋問題」條列照單修改
誰寫程式：有證據的與沒試過的

實際跑完三個專案的組合是 Claude Code 派工＋Codex 寫程式＋Gemini 生圖與配音。 Codex 這一塊有 17 份任務單與 14 筆 commit 可查。

只有 ChatGPT 的話，Codex 本來就是它的；只有 Claude 的話，Claude Code 可以一手包辦，生圖改用免費額度或純程式風格包。 只有 Gemini 的情況沒有實測過——Gemini 在這些專案裡負責的是配音、配樂與生圖，不是寫程式。要走這條路請自己先試。

這套流程裡沒有「剪接」這一步

傳統是拍素材 → 剪輯軟體排時間軸 → 剪。這套是配音 → 自動對時 → 程式照著時間軸把每一格算出來。畫面是算出來的，不是剪出來的。唯一接近剪接的只有最後混音，一行指令。

02腳本：一句只講一件事

腳本是一個資料檔，每句標 id、場景、語言、中文、英文、句後停頓。台語另外標拼音。旗標 hook 標開場鉤子、chapter_break 標章節斷點。

{
  "id": "n03",
  "scene": "curve",
  "kind": "narr",
  "zh": "第一秒吹出來的量，叫做 FEV1。",
  "en": "The volume blown out in the first second is the FEV1.",
  "pad": 0.4
}

pad 是句後停頓秒數。留白寫在腳本裡，不是之後剪出來的。

科普敘事的五條文法

  1. 先判斷這一幕在做哪一種教學任務——定義／步驟／比較／因果／分類／問題解答。每一種有自己的出場順序與停留時間，順序錯了觀眾看不懂。
  2. 畫面要「證明」旁白，不是裝飾旁白。說「氣道變窄」就要真的看到管徑縮小，不是放一個氣喘的圖示。
  3. 閱讀時間——畫面上的字要留夠時間讀完，這是可以算的，不是感覺。
  4. 抽象概念要具體化，而且選有過程的動作。有過程才有東西可以動。
  5. 先留缺口再補上。先讓人產生疑問再給答案；直接給答案的，聽完就忘了。

出處：explainer-grammar.md，改寫自 code-animation-explainer（MIT）。

03配音：三件事，加一個反直覺的檢查

一　語氣要比喻一個人

不要只寫形容詞。實際用的那一段：

voice_source.style 原文

Taiwanese Mandarin accent (台灣口音), like a kind senior hospital pharmacist teaching new pharmacists: warm, clear, natural rise and fall, medium-slow pace with natural pauses. Not a broadcast voice, not a mainland China accent. Read English abbreviations letter by letter in English.

它有三層，缺一層效果就差：比喻一個具體的人、排除項（不要播音腔、不要中國口音）、處理規則（縮寫逐字母唸）。

二　縮寫先做一張唸法表

送去配音前替換，字幕照原文。

FEV1 → F E V one      COPD → C O P D      ICS → I C S
FVC  → F V C          PEF  → P E F        0.7 → 零點七
ICS-formoterol → I C S formoterol         2026 → 二零二六

三　停頓寫在腳本裡

每句的 pad。用 Edge TTS 當備援時另外調語速與音高（--rate=-14% --pitch=-6Hz）。混音比例：音樂 −14 dB、音效 −18 dB（相對旁白），整體 −16 LUFS。

破音字：不能用一般語音辨識回頭檢查

為什麼不用 Whisper 檢查

它有很強的語言模型，會把唸錯聲調的字猜回正確的字——唸成「重新踩」也會寫成「重新猜」，所以抓不到錯。

解法是用沒有語言模型的 CTC 模型，逐格輸出實際聽到的音：

  1. 兩個離線 CTC 模型各辨識一次（sherpa-onnx 的 zipformer-ctc-zh 與 SenseVoice），互相印證
  2. 辨識結果與旁白都轉成帶聲調拼音（pypinyin），逐字對齊
  3. 兩個模型都聽成別的音 → 判「讀錯」；只有一個不同 → 「待確認」
  4. 平翹舌不分（zh/z、ch/c、sh/s）不算錯，那是台灣口音的常態

送去配音的文字可以用同音字繞過唸錯（「手繪」→「手慧」），但比對時以字幕的讀音為準——觀眾聽到的要和字幕一致。

實績：抓到「猜→踩」「手→受」「繪→回」「幾幕→繼母」「報→寶」。醫療名詞特別容易中：鞘、瘜、嚥、賁、咳。需要 pip install sherpa-onnx pypinyin，模型約 400 MB。

一條鐵律

AI 無法驗收聲音：每次改配音都要人聽。這是整個流程裡唯一機器不能代你驗收的一步。

操作坑：下載到上一段的檔案

網頁版語音工具按 Run 不一定真的跑起來，這時下載會拿到上一段的檔案。對策：下載前先確認播放器總長和上一段不同（document.querySelector('audio').duration，生成中會是 0.04），檔案入庫後再比對 sha256，相同就是抓錯。另外三段要在同一個前景分頁依序錄，背景分頁收不到點擊。

04時間軸：全片不寫死任何秒數

配音完成後用語音對齊取得每一句、每一個詞的實際時間，寫成一個檔案：

// build/timeline.json（對齊後自動產生）
"lines": [
  { "id":"n06", "start": 40.6, "scene":"heart" },
  { "id":"n07", "start": 43.6, "scene":"heart" },
  { "id":"n08", "start": 47.3, "scene":"heart" }
]

畫面、字幕、音效、配樂的時間點全部從這個檔案讀。程式裡沒有一個寫死的秒數。

程式怎麼把它變成影片

影片就是每秒 30 張圖。5 分鐘 = 9000 張。程式不「畫動作」，它回答一個問題：第 t 秒這一格長什麼樣？

  • 畫面本身是一張網頁，渲染器逐格把它輸出成圖
  • 某個字要在第 40.6 秒出現？程式去時間軸查，自己算出這一格該不該出現、出現到什麼程度
  • 9000 格跑完接起來，就是影片。全片渲染 15–20 分鐘
這是整套流程能一直改下去的唯一原因

腳本改一句 → 重跑兩個指令 → 整片自動對齊，包括字幕、音效、配樂。手動剪輯的話，插一句話要重排後面所有東西——所以第一版做完通常就定型了。

動畫事件綁在「line id ＋ 詞」上（例：s03:每天），主要變化發生在該詞唸出的 ±0.2 秒內。另一條硬規則：畫面不可比旁白早出現。

05生圖：三個固定做法

  • 畫風前綴——每張圖的提示詞開頭貼同一段風格描述，整片視覺才統一。
  • 角色設定卡——有角色出場就貼該角色的固定描述，並要求「保持完全相同」。同角色的後續姿勢要在同一個對話裡續生，衣著每次寫明。
  • 貼圖集——同一場要很多小元件時，不要一張圖生一個。改成一張 2752×1536 的綠底圖排成格狀，下載後由程式依連通區域切件去背。一張可放 12–20 個，省掉大半生圖額度。

流程：綠底姿勢圖 → 放大 ×4 → 同框去背 → 存成零件。

坑：生圖工具的「下載原尺寸」對續生圖會回傳最早那張；改用頁面覆蓋原圖擷取，再放大。

先做畫風測試再量產：同一個場景請它畫 2–3 種風格各一張，選定後才開始。角色細節多交給 AI 畫；曲線和數據要準，交給程式畫。

06動畫五層：運動與揭露最常被跳過

層內容
⑤ 風格手繪／水墨／拼貼／檔案／扁平
④ 鏡頭推拉搖移、長卷平移、視差、焦點引導
③ 揭露遮罩推進、路徑描繪、錯開、形變、溶接
② 運動預備、跟隨、重疊、弧線、擠壓、次要運動
① 時間緩動、彈簧、節奏、與旁白同步
第②③層最決定成敗，也最常被跳過

只有淡入和線性位移的畫面，不管美術多好都會被看成投影片。

揭露層解開的死結

手繪動畫不是用程式畫出來的。先準備一張完整的圖（AI 生圖或手繪都可以），再用遮罩控制它出現的順序與方向，筆尖跟著遮罩邊緣走。

細節在圖裡，動畫在遮罩上。

沒有筆尖的遮罩推進看起來像擦窗戶。遮罩的 feather 設 0 是硬邊（紙被撕開），設大是柔邊（顯影）。

鏡頭層

把所有章節排在同一張長卷上，讓鏡頭滑過去。一張一張切是翻投影片；鏡頭在同一個世界裡移動，觀眾才有「我們在前進」的感覺。

  • 視差：背景 .85、中景 .5、主體 0。沒有視差的橫移不管畫多好都是平的。
  • 章節交接不能直接平移（像在拖一張大圖），中間要先拉遠再推回，才像鏡頭飛過去。
  • 焦點引導：旁白在講左邊那個東西時，鏡頭偏一點過去就夠，不必整個飛過去。
  • 長卷的間隔必須大於畫面寬，否則相鄰章節穿幫。

運動層常用的函數

函數用途
anticipate預備動作。要往右走之前先往左縮。沒有這個，所有運動都像瞬移
spring物理彈簧。比任何曲線都自然，因為有質量
stagger錯開。一群東西不要同時進場
arc弧線路徑。真實的移動不走直線
hold進場→停留→離場。很多人只寫進場忘了離場
settle次要運動。主體停了，布料／紙張邊緣還在晃
breathe永不停止的細微起伏，讓靜止的畫面不死。幅度 1–2%

07判例準則：規則＋判例＋自檢問題

寫法是三者缺一不可。規則可以有意識違反，但每次違反要寫明理由。編號發布後不重排，只追加（R 節奏／Q 畫面／T 文字／S 聲音／P 流程／C 鏡頭）。

自檢問題全是白話——術語是 agent 的事，自檢問題是你的事。

R1

勻速運動讀作廉價 PPT

規則
飛入、滾動、位移一律用非線性緩動；一群元素入場要「越來越快」，最好綁一個物理隱喻（發牌、骨牌、落葉）。
判例
某專案連續四版畫面被評為「只是投影片」，根因不是美術而是運動——所有東西都是透明度 0→1 加線性位移。
自檢
畫面上有沒有任何元素在做勻速直線運動？批次入場是否越來越快？
R2

關鍵資訊落定後必須呼吸，至少靜止 1 秒

規則
承載資訊的元素（標題、數字、圖表全貌）落定後靜止 ≥1s 再切。呼吸給重點，不要隨手給普通元素。
自檢
每個「想讓觀眾記住的畫面」有沒有完整的靜止時刻？
R3

節奏寧慢勿快，初版預設放慢一檔

規則
主體動作弧（聚焦→移動→歸位）至少 3 秒；模擬真實操作按人真實的速度；排時間線時預留停頓預算。
判例
全片六次獨立回饋全部指向「放慢／停留」，從未有一次「太慢了」。
自檢
把每個鏡頭當第一次看——哪裡沒看清？
R4

一種手法全片只當一次主角

規則
飛入、堆疊、翻頁、暈開，每種手法全片只能當一次主角；同一素材或同一資訊只出現一次，重複即刪。
自檢
有沒有兩個鏡頭在用同一種手法當主角、或講同一件事？

鏡頭（C）與畫面（Q）的主要條目

  • C1 運鏡有預算，超過就是在晃
  • C2 推近倍率低於 1.25× 讀作晃動
  • C3 推近的終點必須是一個說得出名字的東西
  • C4 相鄰兩幕不同景別，但不跳級
  • C5 結尾回到全景，不停在推近狀態
  • C6 每一幀都要能當封面
  • C7 視線引導線就是鏡頭動線
  • Q1 開場只給一個主角　Q2 鏡頭要穩，預設不加手持抖動
  • Q3 光效寧缺勿濫：不群發，一鏡最多給主角一次
  • Q4 精細不等於擁擠：每個元素都要有理由
  • Q5 元素落定要有真實位置，不懸浮

格式與多數條目改寫自 video-shotcraft（Apache-2.0）的 aesthetic-rules，只收與題材無關的條目。

08檢查：機器只擋「一定錯」的

必修（會擋住，不能出片）

  • 規格、片長
  • 整體音量（目標 −16 LUFS）、峰值爆音（dBTP）
  • 非預期的黑畫面——會自動扣掉刻意的黑：冷開場、章節黑幕、燈滅、片尾
  • 缺圖
  • 字幕超過兩行、字幕行首是標點
  • 排版四項：重疊、超出安全框、壓到字幕區、文字超出卡片、字級小於 28px

建議（只列出來，由人決定）

同一鏡頭停太久、鏡頭太短、字幕每秒字數可能讀不完、音效庫缺檔。

只有人看得出來的十四項

圖示一看就懂（否則改文字）、元素不重疊不出框不壓字幕、方向（角色朝向＝移動方向、同段航向一致）、角色外觀與年齡一致、道具合乎時代（中式油燈不要阿拉丁燈）、旁白與畫面一致、同畫面不停太久、斷句、轉折有鋪陳、段落留白、空間關係、字幕斷行、台語發音、音樂不蓋旁白、角色是否容易被誤認（新妻與前妻服裝要區隔）。

驗收問的那一句

每句中點圖用全尺寸逐張看，逐張回答：只看畫面、不聽旁白，新手知道這在講什麼嗎？

總覽縮圖只用來看結構，看不出字距與小重疊。沒有配字、新手一看不懂的圖示，一律不用。

一個寫、一個看

寫程式的 AI 開不了瀏覽器，看不到自己做出來的畫面。所以分成兩個角色：一個寫程式，另一個輸出截圖、逐張檢查，再寫下一輪的修正單。你只看最後的總覽圖和影片。

停損

每輪只修必修＋使用者點名的問題；建議累積到下一版；兩輪內無必修即完成。新坑出現才加檢查，不預先加。

09視覺規格（扁平風為例）

  • 零件至少三層：底色漸層、暗面、高光；主角零件有柔和外光暈
  • 主體佔畫面 50–70%
  • 顏色固定編碼，而且同時搭配形狀或文字，照顧色盲；優先藍／橘，避免紅／綠
  • 新名詞出現時浮出小標籤：縮寫 56px ＋ 中文 40px ＋ 一句白話 30px
  • 一個畫面只介紹一個新詞；第二次出現再提醒一次
  • 畫面文字只放名詞標籤、圖表軸與數值、選項、一兩個字的圖示標註；不重複旁白句子
  • 鏡頭最短 1.2 秒，同場換景別用硬切
  • 同一畫面不要靜止超過約 4 秒；持續有微動
  • 指引定義用「指引原文卡」樣式並標出處（Box／頁碼），與例子分開呈現
  • 輸出 1080p 30fps，另出 720p 預覽

舞台用漸層＋漂浮光點，不畫寫實背景，不要方框面板。

10風格包：依題材六選一

風格適合題材畫面來源成本

11四個踩過的坑

一　配音有雜音，問題不在 AI

現象：每句開頭一聲爆音，結尾一段滿格雜訊。
原因：回傳的音檔尾端附了一段來源驗證的中繼資料，而寫檔程式把整個回傳內容當成音訊樣本寫出去。
對策：解析出真正的音訊段落重寫。十四個檔案無損修復，沒有重新呼叫 API，發音語氣完全沒變。

聽起來像 AI 不穩，常常是自己的寫檔那一步。

二　字幕斷行

長句在最接近中間的標點後斷兩行；兩行長度平均，不留一兩個字；英文不斷字；中文行首不能是標點。人工看很累，所以寫成機器必修項。

三　方向與角色一致

角色朝向＝移動方向；同一段航程方向要一致；後續畫面在原對話裡續生並要求保持完全相同。不一致時，觀眾覺得怪但說不出哪裡怪。

四　額度與成本

額度用盡會鎖住同一帳單下所有金鑰。對策：貼圖集省生圖額度；配音有快取（以「句子 id ＋文字雜湊」命名，稿子沒改不重打 API，改台詞會自動重生）；長時間渲染排到背景跑。

快取只看 id 不看雜湊的話，改台詞會沿用舊配音，造成字幕與旁白不一致。

附帶一條：改片長要連帶改前後測

句子或停頓一改，時間軸就變，配套的前後測時間戳要跟著更新。某系列曾因此偏掉 6–14 秒。

C　故事片（3–4 分，社區衛教劇情、台語長者、校園推廣；範本：林投姐）

資料自己給：原始來源、寫明版本、先看授權。內容自己審：正式使用前請第二位藥師或醫師審過。聲音自己聽：每次改配音都戴耳機聽一遍。
