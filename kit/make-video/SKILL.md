# 做影片（make-video）

> **公開版說明**：本檔提到的 `scripts/`、`render/` 程式（voices.py、pron_check.py、sfx_lib.py、qc.py、mux.py 等）是作者自己的參考實作，**公開版沒有收錄**。請讓你的 agent 依本檔的規則自己寫；`template/` 裡只留了格式範本（腳本、音效表、分鏡表）。

## 0. 開場：先給建議，不要直接動手
使用者沒說清楚要影片還是文件時，先用一句話確認成品形式。
使用者給主題後，先回覆以下內容並等使用者選擇：
1. 這個主題的 2–3 種敘事結構（例：懸疑倒敘、問題→解答、三段式反轉），各一句話說明。
2. **推薦 1 個風格包、列 1–2 個備選**，用 `styles/` 的「適合題材」對照，說明理由（題材調性、觀眾、成本、是否需要 AI 生圖）。
3. 預估長度、時間與需要的帳號（Gemini 訂閱？只用程式？）。
4. 聲音安排：華語旁白、哪些角色講台語。
5. 使用者只有一個 AI 訂閱時，依 `styles/README.md` 的「單一訂閱」表調整分工。

## 1. 建立專案
- 新資料夾放在使用者指定處（預設桌面 `<主題>動畫`）。複製 `template/story.example.json`、`template/docs/shotlist.example.md` 當格式參考（公開版不含程式範本，程式由 agent 依本檔規則撰寫）。
- 建立 `AGENTS.md`（內容＝本檔第 3–7 節的專案版，寫入選定的風格包名稱與該風格的規則）、`CLAUDE.md` 與 `GEMINI.md`（內容各一行：`@AGENTS.md`）、`docs/develog.md`、`.gitignore`（`.env`、`build/`、`output/`）。
- `template/` 是《林投姐》的參考實作：場景名稱、FX 與 shots 都是該片專用，**新片由 Codex 依新腳本與風格包改寫**，不要直接套用。

## 2. 分工
| 角色 | 負責 |
|---|---|
| Claude Code | 規劃、腳本、分鏡、Prompt、操作 Chrome（Gemini App）、檢查畫面、派工 |
| Codex（不可用時改派 Sonnet 子代理） | 寫程式、去背、放大、深度、混音；做到 stills 驗收為止。子代理看不到畫面，任務單必須寫明每句的「畫面文字」與觸發詞，並要求交件前自己跑排版檢查到必修 0 |
| Gemini App | 生圖、配樂（風格包需要時） |
| 使用者 | 選方向、聽聲音、看片、提意見 |

Claude 用量成本最高：Claude 負責判斷與驗收，寫程式與長時間渲染交給 Codex 或 Sonnet 子代理背景執行。

## 2.5 內容查證與決議（衛教、指引、改編真實題材）

做指引、衛教、改編真實作品或史實的片子，內容錯一句比畫面醜一百倍嚴重。流程固定如下。

1. **先查證再寫腳本**。引用外部來源（指引條文、論文數字、商業作品的玩法細節、歷史事件）一律查原文，不靠印象。查不到就不講，或改成不需要那個細節的講法。曾經踩過的坑：憑印象寫了某款遊戲「不存在的機制」當對比，整段要重寫。
2. **開工前建 `docs/<來源>_查證.md`**，先於腳本。每一項寫：原文要點（改寫，不照抄）、**出處頁碼或編號**、「動畫怎麼講」、「常見誤解」。腳本只能引用這份文件裡有的東西。
3. **頁碼寫法**：寫印刷頁碼，並在文件開頭註明與 PDF 頁序的偏移，另說明怎麼抽查驗證。原始文件內文的交叉引用常寫錯頁，**一律以目錄與實際頁面為準**，不信內文指的頁碼。
4. **文件末尾列「仍需人工確認」**：原文自相矛盾、版本差異、用詞要選一個、超出自己能判斷的範圍，全部列出來，不要自己猜一個寫進腳本。
5. **使用者看過後，在同一份文件補「決議」段落**，把每項分成三類並記下定案：
   - **Claude 可定案**：原文寫法不一致取哪個、頁碼、引用格式、版權處理、哪些細節對觀眾沒用所以不講。
   - **使用者拍板**：講法與用詞（例如同一個門檻有兩個層次，旁白要怎麼講），定案後寫成**一句標準旁白**，整個系列重複使用。
   - **需專業審閱**：臨床或專業判斷。
   決議寫進文件後，各課腳本直接照它寫，不再逐課重新討論。
6. **專業審閱不卡進度**：分批送審，沒有專業主張的課（例如導讀、工具操作）先做，不等審閱回來。
7. **系列片要有名詞分配表**：列「哪一課只是讓人認得這個字、哪一課才正式教學」。第 0 課掃過一遍不等於教過；每個名詞都要有一課負責從頭講清楚，否則會出現「每課都提到、從來沒講懂」的詞。
8. **版權**：圖表全部重繪，不放原圖；引用原文每次不超過一句短語；片尾標出處與版本年份。
9. **名詞要查兩層：原文術語，以及在地的實際用法。** 查了原文中譯不等於查完了——指引／學會的中譯、新聞型衛教、醫院給病人的衛教單張，三者常用不同的詞。做法：原文術語 →  指引或學會中譯 → **搜尋當地醫院的衛教單張怎麼寫**，三者不一致時依觀眾選詞，並把選擇與理由寫進查證文件。選詞的優先順序是「既是當地慣用、又不會指錯事實」；兩者衝突時以事實為準，但要承認慣用法存在。
   踩過的坑：把 GINA 的 airway 一路譯成「氣道」，使用者（藥師）反映台灣習慣講氣管。實際查證發現三種說法在台灣都通行，但分場合——學會發言用氣道、新聞衛教用呼吸道、醫院衛教單張用氣管與支氣管。最後選「支氣管」：台灣衛教慣用、位置正確（氣喘的平滑肌收縮發生在支氣管而非氣管），而且讓「支氣管擴張劑」這個藥名自己解釋自己。**教訓是不要憑印象斷言當地用法**——第一次回答時我說「氣管是口語、專業文件不會用」，查了才發現醫院衛教單張大量使用，那句是錯的。
10. **不准為了遷就工具或省事而改內容。** 查不到就先窮盡手段：文字層 → **該頁的 PDF 影像**（用能讀圖的工具讀那一頁，逐字轉錄進查證文件，再由程式重繪）→ 目錄與交叉引用。真的查不到才列進「仍需人工確認」。
    踩過的坑：原文有幾張純圖的表（PDF 文字層只抽得到註腳），我提議「改引其他文字段落避開那張圖」——那是為了遷就工具而改內容。正確做法是讀那一頁的影像轉錄下來。轉錄之後還額外發現圖上有一條重要提醒是文字層看不到的。
11. **決定不講某段內容時，要寫對理由。** 分清楚「教學範圍取捨」（入門不需要這層）與「原文真的有矛盾」。把取捨記成矛盾，會讓後來的人以為「原文看起來打架就刪掉」是對的做法。自己寫過的決議事後要回頭驗，這次就查出兩筆把取捨寫成矛盾的紀錄，實際核對原文後兩處並不衝突。

## 3. 流程（每步都是：提方案→使用者選→派工→檢查→使用者看→修改）
1. **腳本** `story.json`：每句 `id, scene, kind(narr|tw), zh, en, tl(台語台羅), pad`；旗標 `hook`、`chapter_break`。一句只講一件事；開場用鉤子；轉折要有鋪陳；段落間留白。
   - **寫每一幕之前先判斷它的教學任務**（定義／步驟／比較／因果／分類／問題解答），每一種有自己的出場順序與停留時間，見 [explainer-grammar.md](explainer-grammar.md)。順序錯了觀眾看不懂。
2. **配音** `python3 scripts/voices.py --narr edge` → `build/voice.wav`、`build/timeline.json`（所有時間點唯一來源，不寫死秒數）。
   - **配完一定要回頭查讀音**：`python3 scripts/pron_check.py <story.json> --vo <音檔目錄>`。用無語言模型的 CTC 辨識逐字比對聲調——Whisper 類模型會把唸錯的字「猜回」正確的字，抓不到破音字。醫療名詞特別容易中（鞘、瘜、嚥、賁、咳）。需要 `pip install sherpa-onnx pypinyin`，模型約 400MB。
3. **音效**：用自己建的共用音效庫（例如雲端硬碟裡的「音效庫/freesound」資料夾，只收 Freesound CC0，出處記在 CREDITS.csv）。寫 `assets/sfx_cues.json`（鋪底用 `scenes`、單次用 `at: "<line id>@0–1"`，含 gain/trim/dur），`python3 scripts/sfx_lib.py` 依時間軸產生 `build/sfx.wav`。庫裡缺的音效：在 Freesound 搜尋頁加篩選 `license:"Creative Commons 0"`，取試聽檔 `https://cdn.freesound.org/previews/<前三碼>/<id>_<user>-hq.mp3`（不需登入），下載進音效庫並補寫 CREDITS.csv。程式合成音效（`music.py` 產生、備份為 `build/sfx_synth.wav`）只當備案。
4. **配樂**：依風格包的配樂 Prompt 用 Gemini「創作音樂」（純音樂）分段生成，或程式合成；`music_gemini.py` 依時間軸剪接並 ducking。新場景名稱要加進 `music.py` 別名表。
5. **畫面**：依風格包。AI 生圖時先做「畫風測試」（同場景 2–3 種畫風各一張）讓使用者選。
6. **鏡頭**：寫 `docs/shotlist.md`（景別、運鏡、轉場、cue），轉成 `render/shots.json`。每句寫明「畫面文字」；圖示只是輔助，沒有配字、新手一看不懂的圖示不准用（GINA 片使用者回饋：抽象符號多半看不懂）。指引定義與例子分開呈現，定義用「指引原文卡」並標出處（Box／頁碼）。
   - **動畫手法一律先讀 `animation-craft` skill**：運動（預備、錯開、弧線、擠壓）與揭露（遮罩推進、路徑描繪）這兩層最決定成敗，也最常被跳過。只有淡入和線性位移的畫面，不管美術多好都會被看成投影片。鏡頭用 `lib/camera.ts` 的長卷佈局，不要一張一張切。
7. **渲染**：先 `--stills` 檢查，再全片；`mux.py` 混音到 −16 LUFS；另出 720p 預覽版；同步到使用者的雲端硬碟資料夾方便手機看。
8. **檢查（精簡版）**：`python3 scripts/qc.py output/<片名>.mp4` → `output/qc/<片名>_qc.html`。只有「必修」會擋（規格、片長、音量／爆音、非預期黑畫面、缺圖、字幕超過兩行或行首標點）；「建議」（鏡頭停太久、太短、字幕太快、音效缺檔）列給使用者決定。Claude 再看報告裡的鏡頭總覽圖，依第 7 節清單補充建議。
   - stills 驗收：每句中點圖用全尺寸逐張看，逐張回答「只看畫面、不聽旁白，新手看得懂嗎」；總覽縮圖只看結構，看不出字距與小重疊。
   - 自動排版檢查（最小版，Remotion 專案）：主要元素加 `data-lay` 標記，stills 加 `--check` 檢查重疊、出框、壓字幕、文字超出卡片、字 < 28px，列為必修；故意的重疊用 `data-lay-allow` 豁免。只檢查這 5 項，不做排版引擎。作者的 GINA 指引動畫專案有實作（公開版未收錄）。報告放上雲端硬碟讓使用者先看。
   - 停損：每輪只修必修＋使用者點名的問題；建議累積到下一版；兩輪內無必修即完成。新坑出現才加檢查，不預先加。
9. **看片修改**：使用者以「時間＋問題」條列回饋；先說明每點怎麼改再動手。

## 4. 聲音設定
- 華語旁白（建議）：BreezyVoice 本機台灣華語模型，見 `BREEZYVOICE.md`，`voices.py --narr breezy`。
- 華語旁白（快速備用）：Edge TTS `zh-TW-YunJheNeural`（或 `zh-TW-HsiaoChenNeural`），`--rate=-14% --pitch=-6Hz`；台灣用詞；標點與 `pad` 控制停頓；破音字先單句試聽。
- 台語：意傳 `https://hapsing.ithuan.tw/bangtsam?taibun=<台羅>`，**必須輸入台羅**，對照教育部《臺灣台語常用詞辭典》。鬼魂類角色加濾鏡（見 template `voices.py`），一般角色只調音高。
- 音效：真實音效優先（共用音效庫），只換音效時不必重新渲染畫面，重跑 `sfx_lib.py`＋`mux.py` 即可。
- 混音：音樂 −14 dB、音效 −18 dB（相對旁白），整體 −16 LUFS。
- AI 無法驗收聲音：每次改配音都請使用者聽。
- 配音快取以「句子 id＋文字雜湊」命名（voices.py），改台詞會自動重生；舊版只看 id 會沿用舊配音，造成字幕與旁白不一致。

## 5. 操作 Gemini App（Claude in Chrome）
- 每張圖開新對話，提示自帶完整畫風前綴；不要在第一句說要生很多張（會進入慢速規劃模式）。可開多分頁平行。
- **同角色的後續畫面，在含該角色的對話裡續生**，寫 "Keep EXACTLY the same …"；角色年齡變化要先決定切點。
- 只有前景分頁送得出：navigate → JS 填字 → 截圖一次讓分頁取得焦點 → 點藍色送出箭頭（約 700,588）。
- 下載原尺寸：先重新整理分頁再按「下載原尺寸圖片」，一次一張，用 `scripts/grab.sh <編號> [前綴] [資料夾]` 搬檔。失敗時用 canvas 取 1024 預覽。
- 角色要動：原圖對話裡「移除角色」得乾淨背景，再生「同角色、純綠底 #00FF00」，去背後疊回。
- 換掉某張圖後，要 `upscale.py --only X --force` 與 `depth.py --only X --layers --force-layers` 重建。

## 6. 派工給 Codex
- 一定在**專案根目錄**啟動；沙盒無網路（模型權重先下載：`~/.cache/lintou_models/RealESRGAN_x4plus.pth`、HF 的 Depth-Anything-V2-Large）。
- 單一任務約 2 小時上限、前景 10 分鐘：只做到 stills 驗收，全片渲染由 Claude 背景執行。
- 任務單寫清楚：工作資料夾、禁讀檔（`.env`）、輸入、時間軸來源、每場景動作與座標、要檢查的 stills、輸出檔名。
- Chrome 在 Codex 沙盒無法啟動 → 以 Sharp 後備路徑為準，兩條路徑保持一致；Sharp 卷積核高度 ≥3。

## 7. 看片檢查清單
圖示一看就懂（否則改文字）、元素不重疊不出框不壓字幕、方向（角色朝向＝移動方向、同段航向一致）、角色外觀與年齡一致、道具合乎時代（如中式油燈不要阿拉丁燈）、旁白與畫面一致、同畫面不停太久、斷句、轉折有鋪陳、段落留白、空間關係、字幕（短句一行、長句在標點處平均分兩行、英文不斷字）、台語發音、音樂不蓋旁白、角色是否容易被誤認（如新妻與前妻服裝區隔）。

## 8. 寫作語氣
對使用者的說明、字幕、教學文：繁體中文、平實，不用金句、口號、「不是 X 而是 Y」句型。
